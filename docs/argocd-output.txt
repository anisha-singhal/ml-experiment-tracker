The frontend Deployment is scaled from 2 to 1 by hand. Nothing in Git
changed, so Argo CD treats the live cluster as wrong and puts it back.

$ kubectl scale deployment mltracker-mltracker-frontend -n ml-tracker --replicas=1
deployment.apps/mltracker-mltracker-frontend scaled

  07:12:05Z  spec.replicas=1

  Reverted by Argo CD selfHeal.

The backend Deployment is deliberately exempt from this via
ignoreDifferences on /spec/replicas: the HPA owns that field at runtime,
so reconciling it would mean Argo CD and the autoscaler fighting over
the same number.
